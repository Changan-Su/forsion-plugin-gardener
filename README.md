# 库园丁 Vault Gardener

库越用越脏:标签大小写 / 层级变体、坏 wikilink、frontmatter 缺字段、一个词要在两百篇里改。

**库园丁扫全库、逐条给出前后逐字节 diff、你点批准才落盘、一次一条一文件、全程活动日志 + 撤销台账。**

---

## ⚠️ 首屏就要说清楚:不做什么

这是本批唯一可能改写你已有文件的插件,所以边界先摆在最前面。

- **首版只做「就地改写单个文件的内容」。** 移动 / 重命名 / 归档 / 近重复合并**一律只出待办清单,不执行** —— UI 上没有 delete / rename / move 按钮,插件拿到的只读接缝里也没有这几个口,**本插件不会去要写接口**。
- **没有「全部应用」按钮。** 写入一律单文件、单条、你逐条点。这不是还没做,是刻意不做。
- **不接 AI / Agent。** 不做「跟库聊天」,不做 AI 建议。理由见下面「为什么不接 AI」。
- **不做外链体检**(URL 死活 / 幻觉判定不归这里),只管库内链接。
- **不做正则查找替换**,不引入任何查询语言,**不做「永久忽略名单」**,不做定时 / 后台扫描(App 关了插件就停)。
- **不改 frontmatter 已有值**,只补缺键且值留空,**绝不发明任何值**。
- **不碰**`.excalidraw.md` / `.mindmap.md` / `.deck.md` / `.dossier.md` / `.dashboard.md` / `.db` / PDF / 图片等一切非裸 `.md` 文件;**不删除任何文件**。
- ⚠️ 扫描域按「basename 里只能有一个 `.`」的白名单式判定,所以**文件名本身带点的笔记(如 `v1.2-发布说明.md`)也会被跳过并计入 skipped**。这是为了不误伤任何插件自定义文件类型付出的代价 —— 不是扫漏了。
- 不直接改写当前正在编辑的页面状态(一律走文本层写入),避免与你的打字互相打架。
- ⚠️ **目标文件正开在编辑器里时,批准 / 回滚 / 写报告一律被拒绝**(1.1.0 起)。原因见下面「写入协议」的第 0 步 —— 不是做不到,是做了会毁数据。提案会保持「待审」,你关掉那篇笔记再回来点即可。
- **不去重正文里的重复标签。** 合并标签后正文可能出现「关于 #t 和 #t 的讨论」,插件**不会**替你删掉其中一个 —— 那是句子里的词,删掉会留下「和  的讨论」。frontmatter 的 `tags:` 列表会去重(它是集合),但也只收敛**本次真的改动过的那条列表**里的目标标签。
- **frontmatter 只认 `tags` / `tag` 键**,不扩到 `keywords` 之类;条目**带引号**(`- "foo"`)、**块标量**(`tags: |` / `tags: >`)、嵌套映射(`- a: b`)一律**不碰**。
- **标签匹配不区分大小写**(与 `tag-variant` 同一套口径),**没有「区分大小写」开关**。干跑时的「命中的书面形态」表会把 `#Foo × 12 / #foo × 3` 全摊开给你看,没有任何一种写法被藏起来。

## 怎么用

1. **扫一遍。** 命令面板「库园丁:扫描全库」,或在 inbox 视图点「扫描全库」。**扫描只读文件,一个字节都不会写。**
2. **逐条看 diff。** 在 inbox 点一条提案 → diff 视图逐行显示改前(`-`)改后(`+`)。打开时会**重读文件复核哈希**,文件已被改过就直接显示「已过期,请重扫」,而不是画一份骗人的 diff。
3. **批准。** 点「批准并写入」,只有这一步会写文件,而且只写这一个文件。
4. **后悔了就回滚。** history 视图按天列出每次写入,逐条可回滚。

## 五条规则

| id | 做什么 | 成提案的条件 | 否则 |
|---|---|---|---|
| `broken-link` | 修坏 wikilink | 归一后**恰好一个**候选 | 多候选 / 零候选 → 待办清单 |
| `tag-variant` | 标签大小写 / 层级变体归一 | 簇内 canonical 唯一确定(频次最高,并列取字典序最小) | — |
| `fm-missing` | 补 frontmatter 缺字段 | frontmatter **解析成功**(含「本来就没有」) | `---` 开了没闭合 → 待办清单 |
| `find-replace` | 全库字面查找替换 | 你显式发起 + 单文件命中不超上限(内部常量 200 处) | 超限 → 待办清单 |
| `tag-op` | 标签改名 / 合并 / 层级重构 | 你显式发起 + **目标名合法** + 单文件命中不超上限(同一个 200 处) | 目标名非法 → 当场拒绝、连扫描都不发起;超限 → 待办清单 |

前三条由 inbox 顶部的规则按钮控制;`find-replace` 与 `tag-op` **由你在表单里显式发起**,一次扫描只跑一类。

- `broken-link`:`[[t]]` / `[[t|别名]]` / `![[t]]` / `[[t#锚点]]` / `[[t^块id]]` 都认;**锚点、别名、`!` 前缀逐字节原样保留**,只换目标那一段。原文写的是全路径就给全路径,写的是裸名就给裸名。
- `tag-variant`:**整标签边界**替换,canonical `#project` 绝不会碰到 `#projectx`。frontmatter 的 `tags:` 列表同样归一(只改值,键与格式不动)—— 逗号串 `a, b`、流式数组 `[a, b]`、块序列 `- a` 三种形态都认(**1.1.0 起**);**块标量 `|` / `>` 与带引号的条目仍然不碰**。
- `fm-missing`:必填字段来自设置项,**留空 = 这条规则关闭**(默认就是关的)。补进去的值一律为空。
- `tag-op`(1.1.0 起):三档动作 —— **改名**(`#foo → #bar`,目标名任意,不限于大小写归一)/ **合并**(逗号分隔多个源 → 一个目标)/ **层级重构**(`#a/b → #x/y/b`,**默认连 `#a/b/c` 一起搬**,勾选框可关)。与 `tag-variant` **共用同一个抽取器和同一条替换原语**,所以两者的边界口径永远一致。填完源与目标先点「预览影响」出干跑统计(将影响 N 篇、共 M 处 + 命中的书面形态表),**不点批准就一个字节都不写**。

## 逐字节保真(为什么可以放心让它改文件)

- **绝不归一换行。** CRLF 原样活下来;行切分与合并对任意字符串往返恒等(空串、纯 `\n`、无尾换行、CRLF 全覆盖,check 有专项向量)。
- **Amadeus 块标记行 `<!-- a N -->` 是宿主结构数据,五条规则一律跳过。** 这是本插件的一号毁档面,check 里逐行比对钉死。
- **围栏代码块(```` ``` ```` / `~~~`,未闭合视为到文件末尾)与行内 `` ` `` 一律跳过。** `find-replace` 有「含代码块」开关(默认关),`broken-link` / `tag-variant` 无条件跳过。
- **标签规则(`tag-variant` / `tag-op`)另外跳过四类**(1.1.0 起):行内数学 `$…$`、块级数学 `$$ … $$`、行内 HTML 注释 `<!-- … -->`、跨行 HTML 注释。数学的配对判据比反引号严一档(开 `$` 后必须非空白、闭 `$` 前必须非空白),所以「价格 $5 和 $10」不会被误判成一段数学而漏掉里面的标签。⚠️这四类**只加在标签抽取上**,`broken-link` / `find-replace` 的覆盖面一个字节没变(check 里有逐字节回归向量)—— 把它们塞进查找替换等于静默缩小已经承诺过的覆盖面。
- **行首的 `#` 是标题不是标签**;`#` 前必须是行首或空白,所以 URL 的 `…/p#foo`、链接锚点 `[x](y#foo)`、wikilink 块锚 `[[a#foo]]` 都不会被当成标签。`#foo` 也**绝不会**命中 `#foobar` / `#foo-bar` / `#foo_bar`(抽的是词元不是子串);只有你明确勾上「连子层级一起搬」时,`#foo/…` 才跟着走。
- **frontmatter 区只由 `fm-missing` 触碰**(外加 `tag-variant` / `tag-op` 的 `tags:` 列表),其它规则一个字节都不进去。
- **改写一律行内最小替换**,命中区间左右的字符逐字节保留,不重排、不 trim、不改缩进。

## 写入协议(顺序不许调)

0. **目标文件是不是正开在编辑器里?** 是就**当场拒绝、零写入**(连快照都不写),提案保持「待审」。理由:编辑器手上有一份 ≤800ms 陈旧的副本,我们落盘之后它下一次自动保存会把整篇盖回去 —— 写入「成功」了、读回也一致、台账记着 `applied`,你看到的却是改动凭空消失(状态机对失败记了成功)。这一步同样管**回滚**与**写 audit 报告**(上一份报告写完就被打开了,它极可能正是活动页)。`.gardener/*.json` 与 `.snap` 永远在点开头目录里、不可能是活动页,不设这道闸。
1. 重读文件 —— **读失败即拒写**(读不到 ≠ 空文件)。
2. 哈希与扫描时不符 → 标「已过期」、拒写,**零写入**。
3. 用**与预览完全同一个纯函数、同一份输入**算出改后全文;结果与现状相同 → 短路,不落盘、不写快照、不进台账。
4. 写改前全文快照 → **立即读回逐字节比对**;不一致就中止,**一个字节都不碰目标文件**。
5. 台账追加一条 `writing` → 写后读回校验(台账是恢复的权威,它写不成功就整条不做)。
6. 写目标文件。
7. 读回自校验;不一致**立刻回滚**成改前内容并再次读回校验。回滚成功 → 台账记 `auto-rolled-back` + 弹出常驻错误提示;回滚也失败 → 台账记 `failed` + **停止本次会话一切后续写入** + 报出操作号与快照路径。
8. 一切正常 → 台账 `applied`,**同一文件的其余提案立刻标为「已过期」**(它们的哈希基准已失效),提示重扫。**绝不自动重算** —— 重算等于绕过你已经看过的那份 diff。

回滚同样带守卫:当前内容必须与台账记的「改后哈希」一致才准回滚(否则会吃掉你后来的编辑),快照读不到 / 哈希对不上一律拒绝并说明原因。

第 7 步的「停止本次会话一切后续写入」**只停继续应用提案,不停回滚** —— 硬失败之后你最需要的恰恰是把文件还原回去,而回滚写的是快照原文、风险方向与应用相反,上面四道守卫一个不少。

**进程在第 5、6 步之间被杀**时,台账里会留下一条 `writing`。history 视图把这类条目**单列在最上面**当恢复区,同样给一个「回滚」按钮 —— 它按哈希自己判走哪条路:文件已经是改后内容就用快照还原;文件仍是改前内容说明那次写入根本没落地,只把台账那条结为失败,**一个字节都不碰你的文件**。

## 数据存哪

全部在插件的**工作文件夹**下(默认「库园丁」,插件详情页可改)。

| 路径 | 性质 |
|---|---|
| `<工作文件夹>/.gardener/queue.json` | 派生数据,任何时候可靠一次重扫全量重建 |
| `<工作文件夹>/.gardener/ledger.json` | **权威**,撤销台账,只追加不裁剪 |
| `<工作文件夹>/.gardener-undo/<扫描号>/<操作号>.snap` | **权威**,改前全文逐字节快照,永不自动删除 |
| `<工作文件夹>/Reports/audit-YYYY-MM-DD.md` | 给人读的待办清单,纯 markdown。**派生物,同一天重复写会整份覆盖**(它随时可以由一次重扫重新生成);和别的落盘路径一样写完读回校验,不一致就报错而不是假装写成了 |

- 机器数据一律放点开头目录,文件树里不显示;快照后缀是 `.snap` 而不是 `.md`(落成 `.md` 会被当成你的笔记,可能被页面编译器改写 = 毁档)。
- ⚠️ **撤销快照会占空间。** 插件拿到的接缝是**只读**的,没有删除文件的能力,所以它不会、也不能替你清理 —— 要清理请自行在文件管理器里删掉 `.gardener-undo/`。这里**没有**一个做不到的「清理」按钮。
- 换了工作文件夹之后,读端不做旧文件夹回退:新文件夹里重扫一次即可全量重建(台账与快照留在旧文件夹里,需要时手工搬)。
- **落盘文件一个字都不随语言变**:JSON 里只存 id 与原文,界面在渲染时才映射成中英文。`Reports/audit-*.md` 例外 —— 它按写出那一刻的语言成文(一次性产物,不重解析)。

## 产出如何被再次取用

本插件**不新增任何收集入口**。它唯一的产出是**让你已有的内容重新可被取用**:修好的 wikilink 让双链图与反链恢复、统一后的标签让标签面板与全局搜索命中、补齐的 frontmatter 让多维表 / 日历吃到该页。唯一新增的可见文件是 `Reports/audit-*.md`,纯 markdown,能被全局搜索命中、能被 `[[]]` 引用。

## 为什么不接 AI

1. 核心承诺是「diff 由插件自己算、可逐字节复核、预览等于落盘」。模型产出不可复算,一旦进主线,这条承诺就没有结构性保证了。
2. 需求侧被证明的是**确定性批量操作**(全库查找替换 47,988 浏览 / 650 赞;标签批量改名 46,463 浏览 / 810 赞;Tag Wrangler 1,028,168 下载),不是「AI 园丁」。现存的两种「AI 帮你整理库」形态缺的恰恰是**逐条 diff + 审批闸 + 回滚台账** —— 我们补的是闸门,不是再加一个模型。
3. 这是本批唯一可能毁用户数据的插件,风险预算全部花在写入协议上。

**扩展性契约**:队列 schema 里已经有 `producer` 字段(v1 恒为 `rule`)。将来若接 Agent 作为第二生产者,它只允许追加 `producer:'agent'` 的提案,**必须走同一条计算函数、同一条写入协议、同一份台账,且永不写用户文件**(它只能提议)。数据契约零迁移。

## 中英双语

插件跟随宿主 UI 语言,切换语言时**三个视图不重挂也会立刻变成另一种语言**。

- **不翻**(它们是你的数据 / 机器 id):vault 路径与文件名、标签字面串、wikilink 目标与别名、frontmatter 键名与值、你输入的查找 / 替换串、diff 里的每一行原文、规则 id 与状态枚举、操作号 / 扫描号 / 哈希。
- **默认工作文件夹永远是中文的「库园丁」**,不随语言变 —— 否则切一次英文就像换了个数据目录。
- ⚠️ **已知缺口**:宿主的贡献点标题目前是单字符串(命令面板条目、视图标签页标题、设置项 label),**没有运行时重解析**。插件在注册时取当时的语言,所以**切换语言后这三处要重开 Forsion 才跟上**。这是宿主侧的已知缺口;本插件**刻意不为它做重注册 / 自我 teardown 的绕法**——那会打断正在跑的扫描和已经打开的视图。

## 兼容与降级

- 08-14 新增的只读枚举接缝(`listPages` / `listFiles` / `searchVault`)与语言接缝(`getLocale` / `subscribeLocale`)全部可选链,缺席时优雅降级,`setup` 绝不抛错。
- **枚举三态严格区分**,文案各不相同:接缝缺席(旧宿主)→「当前宿主版本不支持库枚举」;接缝在但返回空 →「库里没有可扫的笔记(或当前没有打开笔记库)」;接缝在但调用失败 →「库枚举失败:…」。**空数组绝不当成「旧宿主」**。
- ⚠️ `searchVault` **只用来排序,绝不用来过滤**。宿主的索引是硬截断到 50 条的,而本插件的头号立项理由恰恰是「一个词要在两百篇里改」—— 拿它当候选集就等于静默只改前 50 篇。所以查找替换**永远全量复核**(受 `maxScanFiles` 钳制),索引命中的排在队列最前面,只在真的触到扫描上限时决定谁先被扫;它缺席、返回空或抛错,覆盖面都不变。**命中判定只认真正读回来的文本。**
- ⚠️ `listFiles()` 看不到点开头的目录,`.gardener-undo/` 整棵不在它的枚举里,所以「孤儿快照」不能靠枚举找。插件改成**按当前 `queue.json` 里的操作号主动探测**快照文件是否存在(最多探 200 条)。**能力边界**:queue.json 每次重扫整份覆盖,历史扫描的操作号已不可知,所以它只查得出**当前这一轮**的孤儿。真正的恢复权威始终是台账里的 `writing` 条目(history 视图顶部单列)。
- 旧宿主缺 `achievements` / `activity` / `notify` / `registerStatusItem` / `workFolder` 时全部静默降级,工作文件夹回退到「库园丁」,界面回退中文。
- `ctx.app.getActivePage` 缺席(更旧的宿主)时,活动页闸整条降级成**不拦**(与 1.0.0 行为相同),`setup` 不抛。diff 视图上那条提示是**告知性**的(插件没有活动页变化的订阅,可能滞后一次渲染);真正的闸永远是批准时的那一步。

## 设置

| 键 | 默认 | 说明 |
|---|---|---|
| `rules` | `broken-link,tag-variant,fm-missing` | 启用的规则,与 inbox 顶部的规则按钮互为镜像(同一个存储键) |
| `fmRequired` | 空 | frontmatter 必填字段,**留空 = 关闭 `fm-missing`** |
| `maxScanFiles` | 2000(50–20000) | 单次扫描文件数上限,超出的记进待办清单 |
| `maxFileKB` | 512(16–4096) | 单文件大小上限,超过的跳过并记进待办清单 |

另有宿主自动提供的「工作文件夹」。单文件命中上限(200 处)是内部常量,不做成设置项 —— 它是「一条提案 = 一屏能看完的 diff」这条产品约束,不是调参旋钮。

## 安装

```bash
sh install.sh dev    # → ~/.forsion-dev/plugins/vault-gardener
sh install.sh prod   # → ~/.forsion/plugins/vault-gardener
```

重开 Forsion 后:命令面板「库园丁:打开」,或工作台切到「库园丁」Space(左 inbox + 主 diff + 右 history)。
